# Обновления системы

Система проверяет обновления **при каждом запуске** (`start.bat`), скачивает
новую версию, проверяет её целостность, делает резервную копию и применяет
изменения. Данные базы при этом сохраняются: обновляется только код,
зависимости и схема БД (миграции).

## Как это работает

1. `scripts/start.ps1` на шаге **2.5** вызывает `scripts/update.ps1`.
2. Обновлятор читает манифест `version.json` по адресу из `.env` (`UPDATE_URL`).
3. Сравнивает версию манифеста с версией из файла `VERSION`.
4. Если версия новее:
   - скачивает архив с кодом;
   - сверяет SHA256 с манифестом (защита от повреждения и подмены);
   - копирует текущий код в `backups\app-<версия>-<дата>.zip`;
   - распаковывает архив поверх проекта (**не трогая** `.env`, `.venv`,
     `media`, `_install`, `logs`);
   - если изменился `requirements.txt` — доставляет библиотеки
     (из локального комплекта `_install\wheels`, без интернета);
   - применяет миграции базы;
   - записывает новую версию в `VERSION`.
5. Если сервер обновлений недоступен или что-то пошло не так — система
   **продолжает запуск на текущей версии** (запись в `logs\update.log`).

## Формат манифеста

```json
{
  "version": "1.0.1",
  "date": "2026-10-21",
  "url": "https://github.com/Ara2030/college_info_sys/releases/download/v1.0.1/CollegeIS-1.0.1.zip",
  "sha256": "663C8596EC46606B7E909A8C1F9CB0ED3FAA58C86C0452415956C8ED176FB9F5",
  "notes": "Исправлены даты в формах"
}
```

`url` может быть и сетевым путём (`\\server\share\CollegeIS-1.0.1.zip`) или
`file:///C:/Updates/CollegeIS-1.0.1.zip` — удобно, если в колледже нет интернета
и обновления разложены по сетевой папке.

## Настройки (в `.env`)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `UPDATE_URL` | ссылка на GitHub Releases проекта | адрес манифеста |
| `UPDATE_AUTO` | `True` | `False` — только сообщать о новой версии, не устанавливать |

Отключить проверку разово: `start.bat -SkipUpdate`.

## Выпуск новой версии

```powershell
# 1) поднять версию в коде и собрать архивы
powershell -ExecutionPolicy Bypass -File scripts\release.ps1 -Version 1.0.1 `
  -Notes "Исправлены даты в формах"

# 2) опубликовать на GitHub (нужен gh CLI) — или загрузить вручную
powershell -ExecutionPolicy Bypass -File scripts\release.ps1 -Version 1.0.1 `
  -Notes "Исправлены даты в формах" -Publish
```

Результат в `dist\releases\`: `CollegeIS-1.0.1.zip` и `version.json`.
При публикации на GitHub ассеты должны называться так же — тогда адрес
`.../releases/latest/download/version.json` работает без правок.

Если публикуете вручную, выложите **оба** файла рядом и поправьте `url`
в манифесте на фактический адрес.

## Откат

```
backups\app-1.0.0-20261021-123618.zip
```

1. Остановите сервер (`Ctrl+C`).
2. Распакуйте архив поверх папки проекта (не удаляя `.env` и `.venv`).
3. Запустите `start.bat` — миграции применятся автоматически.

Хранятся 5 последних резервных копий, старые удаляются автоматически.

## Ограничения

- Обновляется **код**, а не дистрибутив Python/PostgreSQL. Переход на новые
  мажорные версии этих компонентов выполняется переустановкой (Setup.exe).
- Если обновление меняет структуру БД необратимо, откат кода потребует
  восстановления дампа — делайте `scripts\backup_db.ps1` перед крупными
  обновлениями.
- На компьютере без интернета укажите `UPDATE_URL` на сетевую папку.
