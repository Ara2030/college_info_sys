## ВВЕДЕНИЕ

Современное среднее профессиональное образование (СПО) характеризуется
значительными объёмами данных, подлежащих обработке: сведения о контингенте
обучающихся, текущая успеваемость и посещаемость, результаты промежуточной
аттестации, учебные планы и расписания, кадровый состав, а также регулярная
статистическая отчётность в учредитель и надзорные органы.

Актуальность темы обусловлена следующими факторами:

- высокие требования государства к достоверности и своевременности сведений,
  передаваемых в Реестр студентов СПО и органы управления образованием;
- необходимость автоматического формирования статистических отчётов
  (СПО-1, СПО-2, мониторинг Минпросвещения России);
- рост нагрузки на учебную часть и административный персонал колледжа;
- потребность студентов, родителей и преподавателей в оперативном доступе
  к сведениям об успеваемости и расписании;
- интеграция с внешними системами: «1С:Зарплата», СМЭВ, Реестр СПО.

Объект исследования — деятельность колледжа (СПО) по организации
образовательного процесса.

Предмет исследования — автоматизация учётных, контрольных и отчётных
процессов образовательной организации.

Цель дипломного проекта — разработка информационной системы колледжа,
автоматизирующей основные бизнес-процессы и формирование отчётности.

Для достижения цели поставлены следующие задачи:

1. проанализировать деятельность колледжа и существующие программные решения;
2. обосновать выбор технологического стека;
3. спроектировать архитектуру и базу данных информационной системы;
4. реализовать модули: контингент студентов, электронный журнал,
   промежуточная аттестация, формирование расписания, кадровый учёт,
   отчётность и интеграция, авторизация и роли;
5. провести тестирование системы;
6. подготовить документацию.

   академические задолженности, стипендия.
4. **Формирование расписания** — составление расписания занятий на семестр
   с учётом учебных планов, преподавателей, аудиторий и ограничений.
5. **Кадровый учёт** — карточки Т-2, штатное расписание, тарификация,

6. **Отчётность** — СПО-1, СПО-2, мониторинг Минпросвещения, REST API
   Реестра СПО, СМЭВ, экспорт в Excel/PDF.

## 2. ПРОЕКТНАЯ ЧАСТЬ

### 2.1. Требования к информационной системе

**Функциональные требования:**

- ведение личных карточек студентов и сотрудников;
- учёт движения контингента и приказов;
- ведение электронного журнала с оценками и посещаемостью;
- планирование промежуточной аттестации с ограничениями;
- автоматическое формирование расписания с проверкой конфликтов;
- формирование статистических отчётов и выгрузок;
- разграничение доступа по ролям.

**Нефункциональные требования:**

- веб-интерфейс, доступный через браузер;
- СУБД PostgreSQL;
- поддержка одновременной работы пользователей;
- экспорт в Excel, PDF, XML, JSON.

### 2.2. Архитектура системы

Информационная система реализована по архитектуре «тонкий клиент — веб-сервер —
СУБД» (рисунок 1). Пользователи обращаются к веб-приложению через браузер;
серверная часть (Django) обрабатывает запросы, выполняет бизнес-логику
и работает с базой данных PostgreSQL. Отдельные сервисы (выгрузка в Реестр СПО,
интеграция с СМЭВ, «1С:Зарплата») реализованы как программные модули
с протокольной имитацией при отсутствии реальных подключений.

```

│  Пользователи │ ───▶ │  Веб-приложение (Django)      │ ───▶ │  PostgreSQL  │
│ (браузер)    │      │  ┌────────────────────────┐  │      │             │
└─────────────┘      │  │ Модули (приложения):     │  │      └─────────────┘
                     │  │ contingent, journal,     │  │

                     │  │ hr, reporting, accounts  │  │
```

### 2.4. Проектирование модулей системы

**Модуль 2.1 «Контингент студентов»** обеспечивает ввод и хранение личных
данных студентов, учёт движения контингента, формирование приказов
и автоматическую выгрузку в Реестр СПО (XML по XSD-схеме).

**Модуль 2.2 «Электронный журнал»** обеспечивает ведение журналов занятий,
фиксацию оценок и посещаемости, расчёт среднего балла и процента посещаемости,
формирование отчётов и уведомлений преподавателей.

**Модуль 2.3 «Промежуточная аттестация»** обеспечивает формирование
расписания экзаменов и зачётов с ограничениями, ведомости, результаты,
автоматическое создание академических задолженностей и приказов по ним,
формирование списков на стипендию.

**Модуль 2.4 «Формирование расписания»** обеспечивает автопостроение
расписания по учебному плану, автоматическую проверку конфликтов,
публикацию на портале и оперативную корректировку.

**Модуль 2.5 «Кадровый учёт»** обеспечивает ведение карточек Т-2,
штатного расписания, тарификации нагрузки, выгрузку в «1С:Зарплата»
и приказы по личному составу.

**Модуль 2.6 «Отчётность и интеграция»** обеспечивает формирование
статистических отчётов (СПО-1, СПО-2, мониторинг), выгрузку в Реестр СПО
через REST API, интеграцию с СМЭВ, экспорт в Excel и PDF.

**Модуль 2.7 «Авторизация и роли»** обеспечивает разграничение доступа
по 7 ролям, личные кабинеты и адаптивное меню.

### 2.5. Алгоритмы автоматического формирования расписания

**Алгоритм расписания экзаменов (модуль 2.3)**:

1. Для группы задаются дисциплины и дата начала сессии.
2. Для каждого экзамена выбирается ближайшая свободная дата, удовлетворяющая
   ограничениям: не более одного экзамена в день и интервал не менее 3 дней
   между экзаменами группы.
3. Зачёты назначаются по одному в день без ограничения интервала.

**Алгоритм автопостроения расписания занятий (модуль 2.4)**:

1. Для каждого пункта учебного плана (группа, дисциплина, преподаватель,
   часов в неделю) выполняется цикл по количеству часов.
2. Перебор слотов (день недели × номер пары): слот свободен, если группа
   и преподаватель не заняты и преподаватель не имеет ограничения времени.
3. Выбирается свободная аудитория.
4. Создаётся запись расписания; конфликты исключены по построению.
5. Выполняется контрольная проверка всех записей расписания на конфликты.

### 3.1. Структура программного комплекса

Проект реализован на Django и состоит из 7 приложений (таблица 5).
Полная структура приведена в Приложении Б.

Таблица 5 — Приложения системы

| Приложение | Модуль | Назначение |
|---|---|---|
| contingent | 2.1 | Контингент студентов, приказы, Реестр СПО |
| journal | 2.2 | Электронный журнал |

Каждое приложение включает: модели (models.py), представления (views.py),
формы (forms.py), сервисный слой (services.py), маршруты (urls.py),
шаблоны (templates/), админ-панель (admin.py), миграции (migrations/).

### 3.2. Реализация модуля «Контингент студентов»

Модуль реализован в приложении `contingent`. Ключевые возможности:

- CRUD-операции для студентов, групп, приказов;
- поиск и фильтры по группам и статусам;
- проведение приказов (сервис `services/orders.py`) — автоматическое обновление
  статуса студента и запись в журнал движения контингента;
- выгрузка в Реестр СПО (`services/registry_export.py`) — формирование XML
  по XSD-схеме `schema/registry_spo.xsd`, валидация (lxml), контрольная сумма
  SHA-256, журнал выгрузок.

### 3.3. Реализация модуля «Электронный журнал»

Модуль реализован в приложении `journal`. Ключевые возможности:

- проведение занятия с формсетом отметок (оценка 2–5 или «н/а»
  и посещаемость по каждому студенту группы);
- расчёты в `services.py`: средний балл, процент посещаемости, критерий
  низкой успеваемости (посещаемость < 60% или средний балл < 3,5);
- отчёты по группе и по студенту с печатью;
- уведомления преподавателей о студентах с низкой успеваемостью.

### 3.4. Реализация модуля «Промежуточная аттестация»

Модуль реализован в приложении `attestation`:

- расписание экзаменов и зачётов с проверкой ограничений (ручное добавление
  блокируется формой, автопостроение — алгоритм `build_schedule`);
- экзаменационные ведомости с печатной формой;
- внесение результатов: при оценках «2», «не зачтено» или неявке автоматически
  создаётся академическая задолженность (`sync_debts_from_exam`);
- приказ о задолженностях формируется автоматически и интегрируется
  с модулем приказов контингента (действие «Академическая задолженность»);
- стипендия: автоматический отбор студентов (нет задолженностей, оценок 2–3,
  незачётов и неявок) и формирование списка за период.

### 3.5. Реализация модуля «Формирование расписания»

Модуль реализован в приложении `schedule`:

- справочники: аудитории (48), преподаватели, учебный план, ограничения
  времени преподавателей;
- автопостроение по учебному плану (`auto_build`) — свободные слоты
  для группы, преподавателя и аудитории;
- автоматическая проверка конфликтов (`check_all_conflicts`): группа занята,
  аудитория занята в двух группах, преподаватель занят в двух группах,
  недоступность преподавателя;
- портал расписания для студентов и преподавателей (сетка «пара × день»);
- оперативная корректировка — замена преподавателя и/или аудитории
  с проверкой конфликтов.

### 3.6. Реализация модуля «Кадровый учёт»

Модуль реализован в приложении `hr`:

- личные карточки сотрудников (форма Т-2) с печатной формой;
- штатное расписание (должности, ставки, оклады, вакансии);
- тарификация педагогической нагрузки: автоматический импорт из учебного
  плана (часы в год = часы в неделю × 34 недели);
- интеграция с «1С:Зарплата»: JSON-выгрузка нагрузки (ФИО, должность,
  СНИЛС, часы по дисциплинам) с контрольной суммой SHA-256;
- приказы по личному составу (приём, перевод, увольнение) — автоматическое
  применение к карточке сотрудника, печатные формы.

### 3.7. Реализация модуля «Отчётность и интеграция»

Модуль реализован в приложении `reporting`:

- автоматическое формирование отчётов СПО-1, СПО-2, мониторинг
  Минпросвещения — данные собираются из всех модулей системы;
- выгрузка в Реестр студентов СПО через REST API в формате XML —
  отправка сформированной выгрузки на эндпоинт, журнал интеграций;
- интеграция с СМЭВ — запросы сведений из государственных реестров
  (ФНС, СФР, ЗАГС, МВД); при отсутствии подключения запросы фиксируются
  с указанием статуса;
- экспорт данных в Excel (openpyxl) и PDF (reportlab) для передачи
  в учредитель и надзорные органы.

### 3.8. Реализация модуля «Авторизация и роли»

Модуль реализован в приложении `accounts`:

- 7 ролей на основе групп Django (директор, заместитель, заведующий
  отделением, методист, преподаватель, студент, родитель);
- разграничение доступа: миксин `RoleRequiredMixin` и декоратор
  `role_required` для защищённых действий;
- личные кабинеты: студент — успеваемость; родитель — успеваемость ребёнка;
  преподаватель — карточка и расписание; АУП — панель разделов;
- адаптивное меню: разделы отображаются в зависимости от роли;
- страница входа с демо-доступами, выход из системы.
