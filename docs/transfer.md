# Передача информационной системы другому человеку

Документ описывает способы передачи ИС колледжа, состав передаваемых файлов
и порядок развёртывания на новой машине.

---

## Кратко: что и как передавать

| Способ | Что передаётся | Когда использовать |
|---|---|---|
| **1. Архив + дамп БД** (рекомендуется) | ZIP с кодом + `database_dump.sql` | Передача коллеге, преподавателю, заказчику |
| **2. Git-репозиторий** | Код + инструкция (БД отдельно) | Командная работа, обновления |
| **3. Полное копирование с данными** | Вся папка + дамп | Перенос на другой компьютер (свой) |

**Секреты (`.env`) НЕ передаются** — получатель создаёт свой файл
и указывает собственный пароль БД.

---

## Способ 1. Автоматический экспорт (рекомендуется)

### Шаг 1. Создание пакета для передачи

На машине, где система работает:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\export_project.ps1
```

Скрипт выполнит 4 действия и создаст папку `dist/`:

| Файл | Назначение | Размер (пример) |
|---|---|---|
| `college_info_sys_ГГГГ-ММ-ДД.zip` | Исходный код системы (без `.venv`, `.env`, кэша) | ~0,3 МБ |
| `database_dump.sql` | Дамп базы данных со всеми данными | ~0,4 МБ |
| `README_УСТАНОВКА.txt` | Пошаговая инструкция (внутри архива) | — |

### Шаг 2. Передача файлов

Передайте получателю **два файла**: архив и дамп БД. Способы:

- **Облако** — Яндекс.Диск, Google Drive, Облако Mail.ru (проще всего);
- **Флешка / внешний диск**;
- **E-mail** — размер небольшой (менее 1 МБ), вложение проходит;
- **Мессенджер** — Telegram, WhatsApp (файлы до 2 ГБ);
- **Git** — если получатель умеет работать с репозиториями (см. способ 2).

### Шаг 3. Развёртывание у получателя

Получатель распаковывает архив и запускает:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\import_project.ps1
```

Скрипт автоматически: найдёт дамп, запустит PostgreSQL, создаст базу,
восстановит данные и запустит систему.

**Либо вручную** — по инструкции `README_УСТАНОВКА.txt`:

```powershell
# 1. Создать базу
psql -U postgres -c "CREATE DATABASE college_sys ENCODING 'UTF8' TEMPLATE template0;"

# 2. Восстановить данные
psql -U postgres -d college_sys -f database_dump.sql

# 3. Создать .env (скопировать из .env.example, указать пароль postgres)

# 4. Запустить (двойной щелчок)
start.bat
```

## Способ 2. Через Git-репозиторий

Если нужна история изменений и обновления.

### Что делать автору системы

```bash
cd C:\Users\Araik\Desktop\college_info_sys

# Инициализация (один раз)
git init
git add .
git commit -m "Информационная система колледжа (СПО)"

# Публикация на GitHub/GitLab (создать пустой репозиторий на сайте)
git remote add origin https://github.com/пользователь/college-info-sys.git
git push -u origin main
```

`.gitignore` уже настроен — `.env`, `.venv`, `logs/`, `media/`, `backups/`
в репозиторий не попадут.

### Что делать получателю

```bash
git clone https://github.com/пользователь/college-info-sys.git
cd college-info-sys
powershell -ExecutionPolicy Bypass -File scripts\import_project.ps1
```

Дамп БД можно выложить отдельно (в файлообменник) или создать данные
скриптом `python fill_demo_data.py`.

## Способ 3. Полное копирование (перенос на другой свой компьютер)

Скопируйте **всю папку проекта** целиком (включая `.venv` — только если
на новом компьютере та же версия Python и та же разрядность), плюс сделайте
дамп БД:

```powershell
# Копия БД
powershell -ExecutionPolicy Bypass -File scripts\backup_db.ps1

# Восстановление на новой машине
psql -U postgres -d college_sys -f backups\college_sys_ГГГГ-ММ-ДД_ЧЧ-ММ.sql
```

> Копировать `.venv` обычно **не нужно** — окружение создаётся заново
> скриптом `start.bat` за 1–2 минуты. Это надёжнее.

## Шифрование пакета (обязательно для персональных данных)

Дамп БД содержит **персональные данные** (СНИЛС, паспорта, адреса студентов
и сотрудников). При передаче через облако или мессенджер используйте
**зашифрованный архив**.

### Создание защищённого архива

```powershell
# Пароль сгенерируется автоматически (20 символов)
python scripts\encrypt_package.py

# Или свой пароль
python scripts\encrypt_package.py --password "ВашСтойкийПароль"
```

Скрипт создаёт в `dist/`:

| Файл | Назначение |
|---|---|
| `college_info_sys_SECURE_ГГГГ-ММ-ДД.zip` | Зашифрованный архив (**AES-256**, шифруются и имена файлов) |
| `..._ПАРОЛЬ_НЕ_ПЕРЕДАВАТЬ.txt` | Пароль и SHA-256 — **оставить у себя!** |

### Как передавать

```
1) АРХИВ   → через облако / флешку / мессенджер
2) ПАРОЛЬ  → ДРУГИМ каналом (звонок, SMS, личная встреча)
```

Правило: **архив и пароль не должны идти одним каналом**. Иначе шифрование
теряет смысл (если перехватят письмо с архивом, то перехватят и пароль).

### Проверка целостности

```powershell
# Отправитель и получатель сверяют контрольную сумму
Get-FileHash dist\college_info_sys_SECURE_*.zip -Algorithm SHA256
```

Значения должны совпасть — это подтверждает, что архив не повреждён
и не подменён при передаче.

### Распаковка у получателя

Архив открывается **7-Zip**, **WinRAR** или **встроенным средством Windows 11**
(ввести пароль). Альтернативно — тем же `pyzipper`:

```powershell
python -c "import pyzipper; z=pyzipper.AESZipFile('college_info_sys_SECURE.zip'); z.setpassword(b'ПАРОЛЬ'); z.extractall('.'); z.close()"
```

### Что внутри защищённого архива

```
college_info_sys_SECURE.zip
├── database_dump.sql          # данные БД (зашифрованы)
└── college_info_sys/          # исходный код (зашифрован)
    ├── manage.py
    ├── requirements.txt
    ├── start.bat
    ├── .env.example           # шаблон (секретов нет)
    └── ...
```

Секреты (`.env`), виртуальное окружение (`.venv`), кэш (`__pycache__`)
и журналы (`logs/`) в архив **не попадают**.

## Что НЕ передаётся и почему

| Файл/папка | Причина |
|---|---|
| `.env` | Содержит секретный ключ и пароль БД — компрометация безопасности |
| `.venv/` | Привязано к пути и версии Python; создаётся заново |
| `__pycache__/`, `*.pyc` | Кэш байт-кода, генерируется автоматически |
| `logs/` | Журналы содержат историю действий и IP-адреса |
| `media/` | Сформированные выгрузки (создаются заново системой) |
| `backups/` | Содержат полные копии БД (передаётся только свежая при необходимости) |

## Безопасность при передаче

1. **Пароли**: получатель создаёт свои учётные записи; демо-пароли
   (`admin/admin123` и др.) следует сменить сразу после развёртывания.
2. **Дамп БД содержит персональные данные** (СНИЛС, паспорта, адреса) —
   передавайте только доверенным лицам, используйте защищённые каналы
   (облако с паролем, шифрованный архив).
3. **Хеширование дампа**: для контроля целостности можно сверить SHA-256:
   ```powershell
   Get-FileHash database_dump.sql -Algorithm SHA256
   ```
4. **Режим отладки**: в `.env` получателя укажите `DJANGO_DEBUG=False`,
   если система будет доступна другим пользователям в сети.

## Быстрая шпаргалка

```
ОТПРАВИТЕЛЬ:
  1) scripts\export_project.ps1        →  dist\{архив.zip, database_dump.sql}
  2) python scripts\encrypt_package.py →  dist\*_SECURE_*.zip (AES-256)
  3) передать: архив — облаком; пароль — отдельным каналом

ПОЛУЧАТЕЛЬ:
  1) установить Python + PostgreSQL
  2) распаковать архив (7-Zip / WinRAR / Windows 11; ввести пароль)
  3) scripts\import_project.ps1       →  всё автоматически
  4) открыть http://127.0.0.1:8000/
```
