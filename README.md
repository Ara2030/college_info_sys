# Информационная система колледжа (СПО)

Дипломный проект: автоматизация учёта контингента студентов, электронного
журнала успеваемости, приказов и выгрузки сведений в Реестр СПО.

**Модуль «Контингент студентов»** — ввод, редактирование и хранение личных
данных студентов; учёт движения контингента (зачисление, отчисление, перевод,
академический отпуск, восстановление); формирование приказов и автоматическая
выгрузка в Реестр СПО (XML).

**Модуль «Электронный журнал»** — ведение журналов учебных занятий по
группам и дисциплинам; фиксация оценок текущего контроля и посещаемости;
расчёт среднего балла и процента посещаемости; формирование отчётов о текущей
успеваемости для администрации и родителей; уведомления преподавателей
о студентах с низкой успеваемостью (посещаемость менее 60% или средний балл
ниже 3,5).

**Модуль «Промежуточная аттестация»** — формирование расписания экзаменов
и зачётов с учётом ограничений (не более одного экзамена в день для группы,
интервал не менее 3 дней между экзаменами); формирование экзаменационных
ведомостей; внесение результатов аттестации; автоматическое формирование
приказов об академических задолженностях; интеграция с модулем расчёта
стипендий (передача списка студентов, имеющих право на стипендию).

**Модуль «Формирование расписания»** — составление расписания учебных
занятий на семестр с учётом учебных планов, распределения дисциплин по
преподавателям, доступности аудиторий и ограничений времени работы
преподавателей; автоматическая проверка конфликтов (одновременное занятие
аудитории или преподавателя в двух группах); публикация расписания на
веб-портале для студентов и преподавателей; оперативная корректировка
(замена преподавателя, аудитории).

**Модуль «Кадровый учёт»** — ведение личных карточек сотрудников
(форма Т-2); формирование штатного расписания; учёт тарификации
педагогической нагрузки с распределением часов по дисциплинам и
преподавателям; интеграция с «1С:Зарплата» для передачи данных о нагрузке
и расчёта заработной платы; формирование приказов по личному составу
(приём, перевод, увольнение).

**Модуль «Отчётность и интеграция»** — автоматическое формирование
статистических отчётов (СПО-1, СПО-2, мониторинг Минпросвещения); выгрузка
данных в Реестр студентов СПО через REST API в формате XML; интеграция
с СМЭВ для получения сведений из государственных реестров (при наличии
подключения); экспорт данных в форматы Excel и PDF для передачи в учредитель
и надзорные органы.

**Модуль «Авторизация и роли»** — разграничение доступа по ролям
(директор, заместитель, заведующий отделением, методист, преподаватель,
студент, родитель); личный кабинет с адаптивным содержимым; защита
служебных действий; адаптивное меню.

## Возможности системы

**Справочники**
- Отделения (4), специальности (8), учебные группы (42) с привязкой к отделению
  и специальности.

**Контингент студентов**
- Личная карточка студента: ФИО, дата рождения, пол, СНИЛС, гражданство,
  документы, родители, адрес, контакты, номер личного дела.
- Документ об образовании (серия, номер, дата выдачи, организация)
  и реквизиты социальной карты (номер, дата выдачи).
- **Личное дело студента** — печатная форма для архива (полные сведения,
  документы, родители, история движения).
- Поиск по фамилии, имени, номеру дела, СНИЛС; фильтры по группе и статусу.
- Статусы: обучается, академический отпуск, отчислен, окончил обучение.

**Приказы и движение контингента**
- Приказ с пунктами (студент + действие): зачисление, отчисление, перевод,
  академический отпуск, восстановление.
- Приказы формируются **по шаблонам типов** в соответствии с **номенклатурой
  дел** (код и наименование дела) — печатная форма с текстом по шаблону.
- Проведение приказа автоматически обновляет статус студента и пишет запись
  в журнал движения контингента (`StudentStatusHistory`).

**Выгрузка в Реестр СПО**
- Формирование XML-файла по XSD-схеме (`schema/registry_spo.xsd`).
- Валидация файла, контрольная сумма SHA-256, журнал выгрузок, скачивание.

**Электронный журнал**
- Ведение журналов учебных занятий по группам и дисциплинам.
- Фиксация оценок текущего контроля (2–5, «н/а») и посещаемости.
- Автоматический расчёт среднего балла и процента посещаемости.
- Отчёты о текущей успеваемости для администрации (по группам) и родителей
  (по студенту) с печатью.
- Уведомления преподавателей: студенты с низкой успеваемостью
  (посещаемость < 60% ИЛИ средний балл < 3,5), фильтр по группе.

**Промежуточная аттестация**
- Расписание экзаменов и зачётов с автоматической проверкой ограничений:
  не более одного экзамена в день для группы, интервал не менее 3 дней.
- Автопостроение расписания: группа + дисциплины + дата старта → даты
  распределяются алгоритмически с учётом ограничений.
- Экзаменационные ведомости: печатная форма со списком студентов, результатами
  и подписью преподавателя.
- Внесение результатов (2–5, зачёт/незачёт, неявка) — при неудовлетворительных
  результатах автоматически создаётся академическая задолженность.
- Приказ об академических задолженностях формируется автоматически
  (интеграция с модулем приказов контингента).
- Стипендия: автоматический отбор студентов, имеющих право на стипендию
  (нет задолженностей, оценок 2 и 3, незачётов и неявок), формирование
  списка за период с печатью.

**Формирование расписания**
- Справочники: аудитории (48: 32 кабинета, 10 лабораторий, 6 компьютерных
  классов), преподаватели (68).
- Учебный план: дисциплины группы, распределённые по преподавателям,
  с количеством часов в неделю и видом отчётности.
- Автопостроение расписания на семестр: алгоритм находит свободные слоты
  (группа, преподаватель, аудитория) без конфликтов.
- Автоматическая проверка конфликтов всего расписания: занятость группы,
  одновременное занятие аудитории или преподавателя в двух группах,
  недоступность преподавателя.
- Публикация расписания на портале: сетка занятий для студентов (по группам)
  и преподавателей.
- Оперативная корректировка: замена преподавателя и/или аудитории
  с проверкой конфликтов, комментарий к замене.

**Кадровый учёт**
- Личные карточки сотрудников (форма Т-2): общие сведения, паспорт,
  кадровые данные, образование, контакты; печатная форма карточки.
- Штатное расписание: должности, оклады, количество ставок, занятые ставки
  и вакансии.
- Тарификация педагогической нагрузки: период + строки «преподаватель —
  дисциплина — часы», автоматический импорт из учебного плана.
- Интеграция с «1С:Зарплата»: формирование JSON-выгрузки нагрузки
  (реквизиты организации, период, сотрудники с часами по дисциплинам)
  для расчёта заработной платы; контрольная сумма SHA-256.
- Приказы по личному составу: приём, перевод, увольнение; автоматическое
  применение к карточке сотрудника; печатные формы.

**Отчётность и интеграция**
- Автоматическое формирование статистических отчётов: **СПО-1** (сеть
  и численность), **СПО-2** (материально-техническая база),
  **мониторинг Минпросвещения** (сводка) — данные собираются из всех модулей.
- Выгрузка в **Реестр студентов СПО через REST API** (XML): отправка
  сформированной выгрузки на эндпоинт, журнал интеграций.
- Интеграция с **СМЭВ**: запросы сведений из государственных реестров
  (ФНС, СФР, ЗАГС, МВД) — при наличии подключения; без подключения запросы
  фиксируются с указанием статуса.
- Экспорт данных в **Excel** (.xlsx, openpyxl) и **PDF** (reportlab)
  для передачи в учредитель и надзорные органы.

**Авторизация и роли**
- Роли (группы Django): директор, заместитель директора, заведующий
  отделением, методист, преподаватель, студент, родитель.
- Разграничение доступа: защищённые действия проверяют роль
  (миксин `RoleRequiredMixin`, декоратор `role_required`); при недостатке
  прав — страница 403.
- Личный кабинет: студент видит свою успеваемость, родитель — успеваемость
  ребёнка, преподаватель — карточку и расписание, АУП — панель разделов.
- Адаптивное меню: разделы показываются в зависимости от роли.

**Админ-панель**
- Полноценная админка Django со списками, фильтрами, поиском и inline-формами.

## Установка и запуск

### Шаг 1. Подготовка PostgreSQL

Создайте базу данных:

```sql
CREATE DATABASE college_sys ENCODING 'UTF8' TEMPLATE template0;
```

Параметры подключения по умолчанию (переопределяются переменными окружения):

| Параметр | Значение по умолчанию | Переменная окружения |
|---|---|---|
| Имя БД | `college_sys` | `DB_NAME` |
| Пользователь | `postgres` | `DB_USER` |
| Пароль | *(пусто)* | `DB_PASSWORD` |
| Хост | `127.0.0.1` | `DB_HOST` |
| Порт | `5432` | `DB_PORT` |

### Шаг 2. Виртуальное окружение и зависимости

```bash
# Windows (PowerShell)
cd college_info_sys
python -m venv .venv
.\.venv\Scripts\Activate.ps1

# Linux/macOS
cd college_info_sys
python3 -m venv .venv
source .venv/bin/activate
```

Установка зависимостей:

```bash
pip install -r requirements.txt
```

### Шаг 3. Миграции

```bash
python manage.py makemigrations
python manage.py migrate
```

### Шаг 4. Суперпользователь

```bash
python manage.py createsuperuser
```

Демо-доступ (если создавали через скрипт): **admin / admin123**

### Шаг 5. Запуск сервера

```bash
python manage.py runserver 127.0.0.1:8000
```

Откройте в браузере: **http://127.0.0.1:8000**

## Электронный журнал

### Как пользоваться

1. **Журнал** → список групп. Выберите группу.
2. В журнале группы — список дисциплин и проведённых занятий.
3. **«+ Провести занятие»** — выберите дисциплину, группу, дату, номер пары,
   тему и преподавателя. Для каждого студента группы выставляется оценка
   (2–5 или «н/а») и отметка посещаемости.
4. Сохранённое занятие можно открыть и отредактировать.

### Расчётные показатели

| Показатель | Формула |
|---|---|
| Средний балл студента | сумма числовых оценок (2–5) ÷ их количество |
| Процент посещаемости | посещённые занятия ÷ все занятия × 100 |
| Средний балл группы | среднее средних баллов студентов группы |
| Низкая успеваемость | посещаемость < 60% **ИЛИ** средний балл < 3,5 |

### Отчёты

- **Отчёт по группе** (для администрации) — сводка: средний балл группы,
  посещаемость, количество отстающих, таблица по каждому студенту. Поддерживает
  печать (кнопка «🖨 Печать»).
- **Отчёт по студенту** (для родителей) — средний балл, посещаемость,
  все оценки по дисциплинам, журнал посещаемости. Также доступен из карточки
  занятия и отчёта по группе.

### Уведомления преподавателей

Раздел **«⚠ Уведомления»** в меню. Показывает студентов с низкой успеваемостью
с указанием причины (низкий балл / низкая посещаемость) и фильтром по группе.
Критерии заданы в `journal/services.py` (константы `LOW_ATTENDANCE_PERCENT`,
`LOW_AVG_GRADE`).

## Промежуточная аттестация

### Расписание экзаменов и зачётов

Система автоматически контролирует ограничения (ТЗ):

| Ограничение | Реализация |
|---|---|
| Не более одного экзамена в день для группы | `is_group_busy()` — проверка при ручном добавлении и в автопостроении |
| Интервал не менее 3 дней между экзаменами | `has_recent_exam()` — окно ±2 дня от выбранной даты |
| Зачёты — не более одного в день | отдельный путь автопостроения без ограничения интервала |

**Ручное добавление:** форма проверяет ограничения и не даст сохранить
нарушающий экзамен.

**Автопостроение** (`/attestation/schedule/build/`): выбираете группу,
дисциплины, вид аттестации и дату старта — алгоритм последовательно назначает
даты: экзамены через каждые 3 дня, зачёты — по одному в день.

### Экзаменационные ведомости

При создании экзамена автоматически формируется ведомость — пустые строки
по всем студентам группы. Печатная форма (`/attestation/<pk>/print/`) содержит
таблицу с результатами и графой подписи преподавателя.

### Внесение результатов

В ведомости для каждого студента: результат (2–5, зачтено/не зачтено) и явка.
При сохранении неудовлетворительные результаты (2, «не зачтено», неявка)
**автоматически** создают академическую задолженность со сроком ликвидации
(по умолчанию 30 дней, константа `DEBT_DEADLINE_DAYS`).

### Приказы об академических задолженностях

Кнопка **«Сформировать приказ о задолженностях»** на странице задолженностей
создаёт приказ в модуле контингента (`Order` + `OrderItem` с действием
«Академическая задолженность»): номер, дата, пункты по всем активным
задолженностям. Приказ виден в разделе **«📜 Приказы»**.

### Стипендия

**«Расчёт стипендий» → «+ Сформировать список»**: указываете период —
система автоматически отбирает студентов, имеющих право на стипендию по итогам
аттестации за период:

- нет активных академических задолженностей;
- нет оценок 2 и 3, незачётов и неявок.

Формируется период со списком студентов (печать поддерживается). Логика
в `attestation/services.py` (`student_eligible_for_scholarship`,
`build_scholarship_list`).

## Формирование расписания

### Справочники

- **Аудитории** (`Room`): номер, корпус, вместимость, тип (кабинет, лаборатория,
  компьютерный класс), доступность. По ТЗ — 48 аудиторий.
- **Преподаватели** (`Teacher`): ФИО, должность, отделение, e-mail, активность.
- **Учебный план** (`Curriculum`): группа + дисциплина + преподаватель +
  часов в неделю + семестр + вид отчётности (экзамен/зачёт) — распределение
  дисциплин по преподавателям.
- **Ограничения времени работы** (`TeacherUnavailable`): слоты (день + пара),
  когда преподаватель не может вести занятия (например, методический день).

### Автопостроение расписания

`/schedule/build/` — выбираете группу, семестр и тип недели. Алгоритм для каждого
пункта учебного плана распределяет часы:

1. ищет слот (день + пара), где группа свободна;
2. проверяет, что преподаватель свободен и доступен (без `TeacherUnavailable`);
3. находит свободную аудиторию;
4. создаёт занятие — конфликты исключены по построению.

### Автоматическая проверка конфликтов

Раздел **«⚠ Конфликты»** проверяет всё расписание:

| Конфликт | Описание |
|---|---|
| Конфликт группы | у группы уже есть занятие в этом слоте |
| Аудитория занята | одновременное занятие аудитории в двух группах |
| Преподаватель занят | одновременное занятие преподавателя в двух группах |
| Недоступность | преподаватель недоступен по ограничению времени работы |

При ручном добавлении занятия форма блокирует сохранение, если есть конфликт.

### Публикация на веб-портале

- **Расписание группы** (`/schedule/groups/<pk>/`) — сетка «пара × день недели»
  с дисциплиной, преподавателем и аудиторией; цветовая индикация недель
  (каждая / нечётная / чётная); выбор семестра.
- **Расписание преподавателя** (`/schedule/teachers/<pk>/`) — сетка занятий
  преподавателя + ограничения времени работы.
- Каждое занятие можно опубликовать / снять с публикации (кнопка на странице
  конфликтов или в админке).

### Оперативная корректировка

Кнопка **«🔄 Заменить преподавателя/аудиторию»** на занятии: выбираете нового
преподавателя и/или аудиторию — система проверяет конфликты и не даст применить
замену, если слот занят. Можно добавить комментарий к замене.

`/hr/staffing/` — должности с окладами и количеством ставок, занятые ставки

`/hr/tarification/` — периоды тарификации (учебный год). При создании периода

расписания: каждый пункт плана (группа + дисциплина + преподаватель + часы/нед)
становится строкой тарификации; часы в год = часы в неделю × 34 недели.
Сводка по преподавателям с общим количеством часов.

### Интеграция с «1С:Зарплата»

`/hr/salary/` — выгрузка данных о нагрузке для расчёта заработной платы:

- выбирается период тарификации;
- формируется JSON-файл: реквизиты организации, период,

  и нагрузка по дисциплинам (часы в неделю / в год, группы);

Формат задаётся в `hr/services.py` (`build_salary_export`).

| Тип | Эффект |

| Приём | дата приёма, статус «Работает», должность |

| Увольнение | дата увольнения, основание, статус «Уволен» |

Для каждого приказа есть печатная форма.

## Отчётность и интеграция

### Статистические отчёты (СПО-1, СПО-2, мониторинг)

Раздел **«📊 Отчётность»** → **«+ Сформировать отчёт»**. Данные собираются
автоматически из всех модулей ИС:

| Отчёт | Содержание |
|---|---|
| **СПО-1** | Сеть и численность: отделения, специальности, группы, студенты по курсам, кадры |
| **СПО-2** | Материально-техническая база: аудитории, лаборатории, компьютерные классы |
| **Мониторинг Минпросвещения** | Сводка: контингент, учебный процесс, аттестация, инфраструктура и кадры |

Каждый отчёт хранит данные (JSON), контрольную сумму SHA-256 и экспортируется
в Excel и PDF (кнопки на странице отчёта).

### REST API Реестра студентов СПО

`/reporting/registry/` — отправка сформированной XML-выгрузки контингента
на REST-эндпоинт реестра. Настройки в `config/settings.py`:

```python
REGISTRY_API_ENABLED = False   # True — реальная отправка (нужен доступ к серверу)
REGISTRY_API_ENDPOINT = 'https://registry.spo.example.ru/api/v1/students'
```

Без реального подключения запрос фиксируется в журнале со статусом
«Заглушка» — протокол и формат отработаны (код 202).

### Интеграция с СМЭВ

`/reporting/smev/` — запросы сведений из государственных реестров:
**ФНС** (ИНН), **СФР** (СНИЛС), **ЗАГС**, **МВД** (паспорт).
Настройка: `SMEV_ENABLED = False` в settings. Без подключения запросы
фиксируются со статусом «Подключение не настроено» с пояснением;
при `SMEV_ENABLED = True` возвращается имитированный ответ реестра.

### Экспорт в Excel и PDF

- **Excel** (.xlsx, библиотека openpyxl) — таблица «Показатель → Значение»
  по разделам отчёта;
- **PDF** (reportlab) — оформленный документ с таблицами для передачи
  в учредитель и надзорные органы.

### Журнал интеграций

`/reporting/logs/` — все интеграционные события (REST API, СМЭВ):
время, направление, конечная точка, код ответа, статус, данные, ответ.

## Авторизация и роли

### Роли

Система реализована на группах Django (`django.contrib.auth.Group`).
Роли и допустимые разделы заданы в `accounts/roles.py`:

| Роль | Код | Доступ |
|---|---|---|
| Директор | `director` | Полный доступ (включая кадры, интеграции) |
| Заместитель директора | `deputy` | Всё, кроме кадров |
| Заведующий отделением | `head_department` | Контингент, журнал, аттестация, расписание, отчёты |
| Методист | `methodist` | Учебная часть: контингент, журнал, аттестация, расписание, отчёты |
| Преподаватель | `teacher` | Журнал (занятия, отметки), уведомления, расписание |
| Студент | `student` | Личный кабинет: успеваемость, расписание |
| Родитель | `parent` | Успеваемость ребёнка |

### Разграничение доступа

- **`RoleRequiredMixin`** (class-based views) и **`role_required(*roles)`**
  (function-based views) в `accounts/access.py`;
- защищённые действия (создание/редактирование/удаление, проведение приказов,
  выгрузки, интеграции) проверяют роль пользователя;
- при недостатке прав возвращается страница **403**;
- неавторизованный пользователь перенаправляется на страницу входа.

### Личный кабинет

`/accounts/profile/` — содержимое зависит от роли:

| Пользователь | Что видит |
|---|---|
| Студент | Средний балл, посещаемость, последние оценки, ссылки на отчёт и расписание |
| Родитель | То же для ребёнка (связь `parent_of`) |
| Преподаватель | Карточку Т-2, своё расписание, электронный журнал |
| Сотрудник/АУП | Панель разделов по правам |

Привязка пользователя к объектам — модель `UserProfile`
(студент / сотрудник / ребёнок родителя).

### Адаптивное меню

Боковое меню показывает только доступные разделы (context processor
`accounts.context_processors.roles_context`); в шапке — имя пользователя,
роли и кнопка выхода.

## Выгрузка в Реестр СПО

1. Перейдите в раздел **«Выгрузка в Реестр СПО»** (меню слева).
2. Задайте период (обязательно), при необходимости — группу и статус студентов.
3. Нажмите **«Сформировать XML»**.
4. Система:
   - соберёт сведения о студентах и приказах в XML-файл по XSD-схеме;
   - провалидирует файл (lxml);
   - посчитает контрольную сумму SHA-256;
   - сохранит выгрузку в журнал и файл в `media/registry_exports/`.
5. Статус выгрузки:
   - `Готов` — валидация прошла успешно;
   - `Ошибка валидации` — в журнале можно посмотреть список ошибок.

Формат обмена (`schema/registry_spo.xsd`):

```xml
<РеестрСПО версия="1.0" датаФормирования="2026-08-19">
  <Заголовок>
    <ТипСообщения>ВыгрузкаСведенийОКонтингенте</ТипСообщения>
    <ВерсияФормата>1.0</ВерсияФормата>
    <Отправитель> ... </Отправитель>
    <Период> ... </Период>
  </Заголовок>
  <Студенты> ... </Студенты>
  <Приказы> ... </Приказы>
</РеестрСПО>
```

Реквизиты организации задаются в `contingent/services/registry_export.py`,
словарь `COLLEGE`.

## Настройка

Все настройки в `config/settings.py`. Ключевые блоки:

- `DATABASES` — подключение к PostgreSQL (переменные окружения `DB_*`);
- `MEDIA_ROOT` / `MEDIA_URL` — хранение сформированных XML-файлов;
- `LANGUAGE_CODE = 'ru-ru'`, `TIME_ZONE = 'Europe/Moscow'`;
- `DEBUG` — для защиты выключите (`False`) и задайте `ALLOWED_HOSTS`.

## Возможные проблемы

**1. Ошибка подключения к PostgreSQL**
```
connection failed: database "college_sys" does not exist
```
Создайте базу (см. Шаг 1) или укажите другую через `DB_NAME`.

**2. Ошибка драйвера psycopg**
```
ImportError: no pq wrapper available
```
Установите полную сборку: `pip install "psycopg[binary]"`.

**3. Ошибка при импорте моделей в собственном скрипте**
```python
import os, django
os.environ.setdefault('DJANGO_SETTINGS_MODULE', 'config.settings')
django.setup()
```
Запускайте скрипт из корня проекта.

**4. После правки Python-кода сервер не перезагружается**
Сервер запущен с флагом `--noreload` — перезапустите вручную.
