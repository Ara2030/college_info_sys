# Информационная система колледжа (СПО)

Дипломный проект: автоматизация учёта контингента студентов, электронного
журнала успеваемости, приказов и выгрузки сведений в Реестр СПО.

**Модуль 2.1 «Контингент студентов»** — ввод, редактирование и хранение личных
данных студентов; учёт движения контингента (зачисление, отчисление, перевод,
академический отпуск, восстановление); формирование приказов и автоматическая
выгрузка в Реестр СПО (XML).

**Модуль 2.2 «Электронный журнал»** — ведение журналов учебных занятий по
группам и дисциплинам; фиксация оценок текущего контроля и посещаемости;
расчёт среднего балла и процента посещаемости; формирование отчётов о текущей
успеваемости для администрации и родителей; уведомления преподавателей
о студентах с низкой успеваемостью (посещаемость менее 60% или средний балл
ниже 3,5).

## Возможности системы

**Справочники**
- Отделения (4), специальности (8), учебные группы (42) с привязкой к отделению
  и специальности.

**Контингент студентов**
- Личная карточка студента: ФИО, дата рождения, пол, СНИЛС, гражданство,
  документы, родители, адрес, контакты, номер личного дела.
- Поиск по фамилии, имени, номеру дела, СНИЛС; фильтры по группе и статусу.
- Статусы: обучается, академический отпуск, отчислен, окончил обучение.

**Приказы и движение контингента**
- Приказ с пунктами (студент + действие): зачисление, отчисление, перевод,
  академический отпуск, восстановление.
- Проведение приказа автоматически обновляет статус студента и пишет запись
  в журнал движения контингента (`StudentStatusHistory`).

**Выгрузка в Реестр СПО**
- Формирование XML-файла по XSD-схеме (`schema/registry_spo.xsd`).
- Валидация файла, контрольная сумма SHA-256, журнал выгрузок, скачивание.

**Электронный журнал**
- Ведение журналов учебных занятий по группам и дисциплинам.
- Фиксация оценок текущего контроля (2–5, «н/а») и посещаемости.
- Автоматический расчёт среднего балла и процента посещаемости.
- Отчёты о текущей успеваемости для администрации (по группам) и родителей
  (по студенту) с печатью.
- Уведомления преподавателей: студенты с низкой успеваемостью
  (посещаемость < 60% ИЛИ средний балл < 3,5), фильтр по группе.

**Админ-панель**
- Полноценная админка Django со списками, фильтрами, поиском и inline-формами.

## Установка и запуск

### Шаг 1. Подготовка PostgreSQL

Создайте базу данных:

```sql
CREATE DATABASE college_sys ENCODING 'UTF8' TEMPLATE template0;
```

Параметры подключения по умолчанию (переопределяются переменными окружения):

| Параметр | Значение по умолчанию | Переменная окружения |
|---|---|---|
| Имя БД | `college_sys` | `DB_NAME` |
| Пользователь | `postgres` | `DB_USER` |
| Пароль | *(пусто)* | `DB_PASSWORD` |
| Хост | `127.0.0.1` | `DB_HOST` |
| Порт | `5432` | `DB_PORT` |

### Шаг 2. Виртуальное окружение и зависимости

```bash
# Windows (PowerShell)
cd college_info_sys
python -m venv .venv
.\.venv\Scripts\Activate.ps1

# Linux/macOS
cd college_info_sys
python3 -m venv .venv
source .venv/bin/activate
```

Установка зависимостей:

```bash
pip install -r requirements.txt
```

### Шаг 3. Миграции

```bash
python manage.py makemigrations
python manage.py migrate
```

### Шаг 4. Суперпользователь

```bash
python manage.py createsuperuser
```

Демо-доступ (если создавали через скрипт): **admin / admin123**

### Шаг 5. Запуск сервера

```bash
python manage.py runserver 127.0.0.1:8000
```

Откройте в браузере: **http://127.0.0.1:8000**

## Электронный журнал

### Как пользоваться

1. **Журнал** → список групп. Выберите группу.
2. В журнале группы — список дисциплин и проведённых занятий.
3. **«+ Провести занятие»** — выберите дисциплину, группу, дату, номер пары,
   тему и преподавателя. Для каждого студента группы выставляется оценка
   (2–5 или «н/а») и отметка посещаемости.
4. Сохранённое занятие можно открыть и отредактировать.

### Расчётные показатели

| Показатель | Формула |
|---|---|
| Средний балл студента | сумма числовых оценок (2–5) ÷ их количество |
| Процент посещаемости | посещённые занятия ÷ все занятия × 100 |
| Средний балл группы | среднее средних баллов студентов группы |
| Низкая успеваемость | посещаемость < 60% **ИЛИ** средний балл < 3,5 |

### Отчёты

- **Отчёт по группе** (для администрации) — сводка: средний балл группы,
  посещаемость, количество отстающих, таблица по каждому студенту. Поддерживает
  печать (кнопка «🖨 Печать»).
- **Отчёт по студенту** (для родителей) — средний балл, посещаемость,
  все оценки по дисциплинам, журнал посещаемости. Также доступен из карточки
  занятия и отчёта по группе.

### Уведомления преподавателей

Раздел **«⚠ Уведомления»** в меню. Показывает студентов с низкой успеваемостью
с указанием причины (низкий балл / низкая посещаемость) и фильтром по группе.
Критерии заданы в `journal/services.py` (константы `LOW_ATTENDANCE_PERCENT`,
`LOW_AVG_GRADE`).

## Выгрузка в Реестр СПО

1. Перейдите в раздел **«Выгрузка в Реестр СПО»** (меню слева).
2. Задайте период (обязательно), при необходимости — группу и статус студентов.
3. Нажмите **«Сформировать XML»**.
4. Система:
   - соберёт сведения о студентах и приказах в XML-файл по XSD-схеме;
   - провалидирует файл (lxml);
   - посчитает контрольную сумму SHA-256;
   - сохранит выгрузку в журнал и файл в `media/registry_exports/`.
5. Статус выгрузки:
   - `Готов` — валидация прошла успешно;
   - `Ошибка валидации` — в журнале можно посмотреть список ошибок.

Формат обмена (`schema/registry_spo.xsd`):

```xml
<РеестрСПО версия="1.0" датаФормирования="2026-08-19">
  <Заголовок>
    <ТипСообщения>ВыгрузкаСведенийОКонтингенте</ТипСообщения>
    <ВерсияФормата>1.0</ВерсияФормата>
    <Отправитель> ... </Отправитель>
    <Период> ... </Период>
  </Заголовок>
  <Студенты> ... </Студенты>
  <Приказы> ... </Приказы>
</РеестрСПО>
```

Реквизиты организации задаются в `contingent/services/registry_export.py`,
словарь `COLLEGE`.

## Настройка

Все настройки в `config/settings.py`. Ключевые блоки:

- `DATABASES` — подключение к PostgreSQL (переменные окружения `DB_*`);
- `MEDIA_ROOT` / `MEDIA_URL` — хранение сформированных XML-файлов;
- `LANGUAGE_CODE = 'ru-ru'`, `TIME_ZONE = 'Europe/Moscow'`;
- `DEBUG` — для защиты выключите (`False`) и задайте `ALLOWED_HOSTS`.

## Возможные проблемы

**1. Ошибка подключения к PostgreSQL**
```
connection failed: database "college_sys" does not exist
```
Создайте базу (см. Шаг 1) или укажите другую через `DB_NAME`.

**2. Ошибка драйвера psycopg**
```
ImportError: no pq wrapper available
```
Установите полную сборку: `pip install "psycopg[binary]"`.

**3. Ошибка при импорте моделей в собственном скрипте**
```python
import os, django
os.environ.setdefault('DJANGO_SETTINGS_MODULE', 'config.settings')
django.setup()
```
Запускайте скрипт из корня проекта.

**4. После правки Python-кода сервер не перезагружается**
Сервер запущен с флагом `--noreload` — перезапустите вручную.
